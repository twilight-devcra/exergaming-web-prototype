# 페달 & 브레인 — 엑서게임 웹 프로토타입

고정형 사이클을 일정한 속도로 밟으면서 화면의 인지 게임을 함께 푸는 시연용 엑서게임의 웹 프로토타입입니다.

## 실행

빌드 과정이나 외부 라이브러리가 없습니다. `index.html`을 브라우저로 열거나, 로컬 서버로 띄웁니다.

```bash
node server.js   # http://localhost:5173
```

- 페달링: `A` / `D` 키를 번갈아 누르기 (한 번 = 반 바퀴), 또는 아래의 페달 센서
- 터치: 마우스 클릭
- 일시정지 `Esc`, 디버그 표시 `` ` ``

## 운영 버전 (체육관 설치용)

`app/` — https://twilight-devcra.github.io/exergaming-web-prototype/app/

- 체육관(어르신 운동 센터)에 설치할 다듬은 버전입니다. 열면 바로 대기 화면입니다 (대기 화면 → 세션 설정 → 라운드 → 결과, 테스트 화면으로 나가는 링크 없음). 페달이 연결돼 있지 않으면 대기 화면에 **페달 연결** 버튼이 보입니다 (브라우저가 새로고침마다 기기를 다시 고르게 하므로). 스테이션 번호는 정하지 않았으면 1 이고 운영 메뉴에서 바꿉니다
- 게임 코드(`js/`, `css/`)는 프로토타입과 같이 씁니다. 운영 버전에서만 바꿀 화면은 `app/index.html` 과 `app/app.css` 에서 다듬습니다. 스크립트에서는 `EDITION === 'app'` 으로 구분합니다
- 화면 스타일은 **풍경 라이딩** 하나입니다 (`js/themes.js` 의 `scenic`, 프로토타입에서는 고를 수 없음). 위 카드에서 하늘·언덕이 점수만큼 흘러가고 길 위 자전거 배지가 공 대신 속도를 보여 줍니다 (`js/band.js` 의 `drawScenic`). 배지 위 말풍선이 RPM 과 할 일(좋아요 / 더 빠르게 / 조금 천천히)을 글로 알려 줍니다. 라운드가 흐르면서 하늘이 아침 → 한낮 → 해 질 녘으로 바뀌고, 지나가는 풍경이 숲 → 과수원 → 마을 → 풍차 들판으로 이어집니다. 속도 전환 구간에는 카메라가 낮아져 길과 길가 풀밭이 화면 대부분을 차지합니다. 풍경 위에 남은 시간(라운드 진행 막대)·달린 거리·점수 칩이 있고, 아래 카드가 인지 게임입니다
- `app/index.html` 이 불러오는 파일 주소에는 모두 `?v=날짜` 가 붙어 있습니다. 고친 것을 올릴 때마다 이 값을 바꿔 주세요 (한꺼번에 바꾸기: 찾아 바꾸기로 `?v=` 뒤 값만). 안 바꾸면 브라우저가 예전 파일과 새 파일을 섞어 써서 대기 화면이 안 뜨고 빈 테스트 화면에 멈출 수 있습니다
- 이름은 **두뇌 PT** (운동하며 인지 건강을 지키려는 분을 위한 '두뇌 퍼스널 트레이닝'), 로고는 `app/logo.svg` (바퀴 안의 두뇌, 브라우저 탭 아이콘도 같음). 대기 화면 오른쪽은 바퀴 안의 두뇌 그림입니다: 바퀴가 한 바퀴 돌 때마다 불꽃이 두뇌로 들어가 신경망이 차례로 밝아지고, 대기 화면에서 페달을 밟으면 그 속도로 빨라집니다 (`app/attract-visual.js`).
- **회원 (QR, 실험)**: 대기 화면 다음에 '회원 카드가 있으신가요?' 화면이 나옵니다. 태블릿 앞 카메라로 회원 QR 코드를 읽거나, 8자리 번호를 누르거나, **손님으로 하기**. 회원은 운동한 날을 표시한 달력과 최근 기록을 본 뒤 세션 설정으로 갑니다 (지난번 시간·난이도가 골라져 있음). 손님은 결과 화면에서 새 회원 번호와 QR 코드를 받고, 오늘 기록이 그 번호로 저장됩니다. QR 은 휴대폰용 회원 카드 주소(`app/card.html#번호`)라 휴대폰 카메라를 비추면 링크가 떠 카드 화면이 열립니다 (결과 화면의 강조한 '새 회원' 칸이 이 순서를 안내). 카드 화면은 회원 카드를 그림(PNG)으로 보여 주고 '갤러리에 저장' 버튼으로 저장합니다 (iPhone 은 공유 창의 '이미지 저장', 그 밖은 내려받기, 그림을 길게 눌러도 됨). 그림 속 QR 은 회원 번호만 담아 칸이 굵어 태블릿 카메라가 작게 보여도 잘 읽습니다. 서버가 없어 기록은 태블릿마다 따로 저장되고(localStorage `exergame.members`), 세션 로그의 `meta.user` 로 업로드됩니다. 번호는 무작위 7자리 + 검사 숫자 1자리라 잘못 누르면 대부분 걸러집니다. 코드는 `app/members.js`, QR 라이브러리는 `app/vendor/`
- **기념물 (마을)**: 회원이 라운드를 마치면 풍경 길가의 이번 점수 자리에 건물을 하나 세웁니다 (라운드가 끝나면 풍경 카드가 화면 가득 커지고, 자전거가 비켜 간 자리에 '오늘 기록으로 짓는 중…' 과 함께 건물이 한 층씩 통통 소리·흙먼지와 함께 올라갑니다. 지붕까지 올리면 반짝이며 '오늘' 팻말과 'N번째 기록 · 집을 지었어요' 가 뜨고, 잠시 뒤 풍경이 줄며 '수고하셨어요' 카드가 나옵니다. 짓는 동안은 눌러도 넘어가지 않습니다. 회원 라운드의 마무리는 약 8초). 종류는 고른 난이도로 정합니다: 편안하게 = 박공지붕 집, 보통 = 줄무늬 차양 가게, 도전 = 깃발 단 뾰족 지붕 탑. 층수는 시간으로: 5·10·15분 = 1·2·3층. 동화책 풍(둥근 모양, 아치 창과 창가 화분, 굴뚝 연기, 검은 선 대신 제 색을 조금 어둡게 한 윤곽)이고 벽·지붕 색은 세션마다 다릅니다. 길 건너편에는 낮게 오르내리는 언덕이 있고, 건물은 그 앞 비탈(꼭대기보다 아래, 길보다 조금 위)에 똑바로 섭니다. 언덕을 먼저 그려 건물·팻말은 가려지지 않고, 밑에 옅은 그림자를 깔아 비탈에 붙어 보입니다. 오르막·내리막에서 길과 언덕은 기울어도 건물은 똑바로 섭니다 (`drawRoadsideHill`). 200점마다 서는 점수 깃발도 같은 비탈에 같은 풍으로 섭니다: 나무 깃대에 펄럭이는 천, 아직 안 지난 것은 크림색 · 1000점마다 큰 깃발은 강조색 · 지난 것은 금색 (`drawScenicFlags`). 다음 라운드부터는 지난 세션들이 그 점수 자리에 서 있어 (날짜 팻말은 곧 지나갈 건물 하나에만 잠깐 보여 마을이 어수선하지 않습니다), 점수가 오르면 자전거가 지난 기록을 하나씩 지나갑니다. 가장 높은 기록에는 별이 있고 그것을 넘으면 '최고 기록 넘었어요!'가 뜹니다. 비슷한 점수로 여러 번 하면 그 자리에 마을이 생깁니다. 기록은 회원 기록(이 태블릿 + 서버)에서 가져옵니다. 주소에 `?marks=objects` 를 붙이면 예전 안(바람개비 · 풍선 · 돌탑)으로 비교해 볼 수 있습니다. 코드는 `js/band.js` 의 `LANDMARK_SETS` · `setLandmarks` · `plant` · `drawLandmarks` · `drawBuilding`, `app/members.js` 의 `landmarks` · `nextCount`
- **운영 메뉴**: 대기 화면 오른쪽 아래의 **⚙ 운영** 버튼, 또는 왼쪽 위 모서리를 2초 누르기. PIN 없이 열립니다 (`APP_OPERATOR_PIN` 이 비어 있음, 다시 쓰려면 네 자리를 넣기). 라운드 중이면 게임이 멈추고, 이어서 진행 / 지금 끝내기 / 중단할 수 있습니다
- **라운드 설정**: 설정은 `js/config.js` 의 `DEMO_CONFIG` 이고 테스트 화면의 저장된 설정과 무관합니다. 운영 메뉴의 **라운드 설정**에서 라운드 난이도 프리셋(어르신·보통·도전)을 고르거나 허용 구역·점수·난이도 항목(`DEMO_SETTINGS`)만 바꿀 수 있고, 태블릿에 저장되어 다음 판부터 적용됩니다 (라운드 중에는 못 바꿈, **기본값으로**를 누르고 저장하면 되돌아감). 스테이션끼리 점수를 비교하려면 운영 메뉴의 **설정 코드**(4자리, PIN 아님)가 모든 태블릿에서 같아야 합니다. 결과 기록과 CSV(`settings` 열)에도 그 판의 설정 코드가 남습니다
- **이 태블릿의 기록**: 결과는 태블릿에도 남습니다 (운영 메뉴 → 이 태블릿의 기록, CSV 저장)
- **무인 운영**: 페달이 끊기면 시간이 멈추고 안내가 뜹니다. 다시 붙으면 이어집니다. 라운드 중 40초 동안 페달도 터치도 없으면 확인 후 결과로 넘어갑니다. 새로고침·뒤로 가기·길게 눌러 메뉴·확대를 막고, 전체 화면이 풀려도 다음 터치 때 다시 들어갑니다. Android 태블릿은 Chrome 의 **화면 고정(앱 고정)** 을 켜 두면 홈·뒤로 버튼으로 나가는 것까지 막을 수 있습니다
- **점검**: 운영 메뉴의 **키보드로 시작 허용**을 켜거나 `app/?kbd` 로 열면 페달 없이 A/D 키로 할 수 있습니다 (새로고침하면 꺼짐, 켜져 있으면 대기 화면에 표시). **게임 건너뛰고 가상 결과 보기**를 켜면 시작하자마자 가상 성적으로 결과 화면이 열립니다 (기록에 남지 않음, 새로고침하면 꺼짐)
- 터치는 Edge·Chrome 에서 확인했습니다. Vivaldi 에서는 터치·펜이 게임에 들어가지 않았습니다
- 스테이션 흐름(대기·결과·운영 메뉴, 무인 운영 장치)은 `js/demo.js` 에 있습니다. 처음엔 프로토타입의 시연 행사용 모드(`index.html?demo`)로 만들었고, 지금은 운영 버전만 씁니다
- **세션 설정**: 로그인 다음에 참가자가 운동 시간(5·10·15분)과 두뇌 게임 난이도(편안하게·보통·도전)를 고릅니다. 모두 Lv1 에서 시작하고, 정답 하나에 오르는 폭은 고른 시간과 난이도로 정합니다 — 다 맞히는 사람이 세션의 90%·70%·50% 지점에서 그 난이도의 최고 레벨(5·7·8)에 닿도록. 값과 식은 `js/config.js` 의 `SESSION_` 상수와 `Config.session`. 페달 허용 구역·점수 같은 나머지는 운영 메뉴의 라운드 설정을 따릅니다. 1분 동안 아무 입력이 없으면 대기 화면으로 돌아갑니다
- **두뇌 쉬는 시간**: 속도 전환 구간은 30초이고, 라운드 시작이나 앞 전환이 끝난 뒤 2~3분(무작위) 지나 다음 인지 게임 대신 나옵니다. 그동안은 문제 없이 페달 속도만 맞춥니다. 5분 세션은 한 번, 10분은 두세 번, 15분은 네 번쯤 (`js/config.js` 의 `shiftSec`, `rpmChangeSegmentSec` ~ `rpmChangeSegmentMaxSec`)
- **음악**: 게임 중 음악은 모두 코드로 합성하고, 어느 스타일이든 비트 하나가 페달 반 바퀴라 페달 박자를 이끕니다. 신나는 댄스(운영 버전 기본, 라운드가 흐르며 소리가 쌓이고 약 1분 반마다 그루브 → 쉬어 가기 → 끌어올리기를 되풀이, 두뇌 쉬는 시간에는 가라앉음) · 산책 기타 · 트로트 · 잔잔하게 · 기본 비트(프로토타입 기본) 중 태블릿마다 운영 메뉴의 **음악** 에서 고르고 **미리 듣기** 로 들어 봅니다 (주소에 `?music=trot` 도 됨). 세션 설정 화면에서는 드럼 없는 잔잔한 음악이 흐르다 측정을 시작하면 줄어듭니다. `js/audio.js` 의 `STYLES`·`ambient`, 목록은 `js/config.js` 의 `MUSIC_STYLES`
- **자동 업로드**: 운영 메뉴의 **자동 업로드** 에 주소를 적으면 끝난 세션을 그 주소로 보냅니다 (인터넷이 끊기면 모아 뒀다가 다시 보냄). 요청 형식과 서버가 할 일은 [docs/SERVER.md](docs/SERVER.md)
- 운영 메뉴의 설정·기록은 localStorage `exergame.demo.*` 에 저장됩니다. 예전 시연 모드와 같은 이름이라, 같은 태블릿에서 시연 모드를 썼다면 그때 기록이 그대로 보입니다

## 세션 로그

한 판(속도 측정 ~ 결과) 동안 일어난 일과 입력 장치의 원시 입력을 기록합니다 (`js/session-log.js`). 형식은 **[docs/SESSION_LOG.md](docs/SESSION_LOG.md)**.

- 테스트 화면: 결과 화면의 **세션 로그 저장** → `exergame-session-<날짜시각>.json`
- 운영 버전: 판이 끝날 때마다(중단된 판 포함) 태블릿(IndexedDB)에 자동 저장. 운영 메뉴 **세션 로그 → 전체 내보내기** 로 한 파일(`.jsonl`, 한 줄에 세션 하나)로 꺼냅니다.
  저장할 때마다 내려받기를 하지 않는 이유: 브라우저가 사람 조작 없는 연속 내려받기를 막아서 무인 태블릿에서 멈춥니다
- 담기는 것: 판 흐름 이벤트, 문제마다 나온 내용·입력·답·걸린 시간, 키 입력 시각, 페달 원시 파형(`CAPD`)과 `WORKOUT`, 게임의 RPM·목표·공 위치 (초당 10번)

## 화면 스타일

기본 · 아케이드 네온 · 스포츠 · 카툰 · 레트로 픽셀 다섯 가지를 비교해 볼 수 있습니다. 색과 글꼴, 속도 띠 그림, 정답·완벽·결과 화면 연출(파편, 꽃가루, 흔들림)이 함께 바뀝니다.

- 테스트 화면 설정의 **화면·소리 → 화면 스타일**, 또는 `T` 키 (게임 도중에도 바뀜)
- 고른 스타일은 태블릿에 저장됩니다. `?theme=neon` 처럼 주소로도 고를 수 있습니다 (`clean`, `neon`, `sporty`, `cartoon`, `pixel`)
- 스타일용 글꼴은 Google Fonts 와 jsDelivr(Galmuri)에서 받습니다. 인터넷이 없으면 시스템 글꼴로 보입니다
- 구성: `css/themes.css` (색·모양), `js/themes.js` (스타일 목록, 속도 띠 그리기 방식), `js/fx.js` (연출 효과)

## 페달 센서 연결

CardioArcade 안드로이드 앱과 같은 Cardio 페달(`Cardio-P xxxx`)을 Web Bluetooth로 연결합니다.

1. Chrome 또는 Edge에서 `http://localhost:5173`으로 엽니다 (Web Bluetooth는 보안 컨텍스트에서만 동작).
2. 메뉴의 **페달 연결**을 누르고 목록에서 페달을 고릅니다. 페어링 요청이 뜨면 수락합니다.
3. 연결되면 키보드 대신 페달 센서로 게임이 진행됩니다. 속도를 재는 방식은 메뉴 설정의 **진행 → 속도 측정 방식**에서 고릅니다.
   - **파형 영교차 (기본)**: 페달의 원시 파형(`CAP`/`CAPD`, 100Hz)에서 반 바퀴마다 케이던스를 구합니다 (`js/cadence-est.js`).
     페달 자체 검출기는 느리게 밟으면 회전을 놓치는데(`DIR_FLIP`), 파형은 그 구간에도 맞는 값을 냅니다.
     2026-10-14 녹화 기준 지연 약 1.4초, 놓침 0%.
   - **파형 결합 / 파형 모양**: 더 빠르지만 느리게 밟을 때 공이 흔들립니다 (비교용).
   - **페달 avg_rpm**: 페달이 1초마다 보내는 값(`WORKOUT`). 지연 약 3.9초, 느리게 밟으면 0으로 떨어질 수 있습니다.
   - 파형 방식이어도 파형이 1초 넘게 끊기면(구 펌웨어 등) avg_rpm 으로 돌아갑니다.

- 라운드 도중 연결이 끊기면 게임이 일시정지되고 자동으로 다시 연결을 시도합니다. 다시 붙으면 이어서 진행됩니다.
- 연결 직후 몇 초 만에 계속 끊긴다면 페어링 키가 한쪽에만 남은 경우입니다. OS 블루투스 설정에서 페달을 제거한 뒤 다시 연결합니다.
- 목록에 페달이 보이지 않으면 휴대폰의 CardioArcade 앱이 이미 페달에 연결되어 있지 않은지 확인합니다.

### 센서 디버그 페이지

`http://localhost:5173/pedal-debug.html` (메뉴 아래의 **센서 디버그** 링크). 게임과 같은 연결·처리 코드로 페달을 붙여서 단계별 값을 보여줍니다.

- 원본 BLE 알림, 프레임별 `avg_rpm`·`watt`·`rev_count`와 수신 간격
- ① 페달이 보낸 RPM → ② 0 유예(`SENSOR_ZERO_GRACE`) 후 → ③ 게임이 쓰는 다듬은 RPM, 그리고 참고용 `rev_count` 기준 RPM
- 목표 RPM을 넣으면 게임에서의 편차와 공 위치를 같이 보여줍니다
- **● 기록 시작**부터 **■ 기록 중지**까지만 브라우저(IndexedDB)에 저장합니다 (5초마다, 탭이 가려질 때, 중지할 때). 그 밖에는 화면에만 보입니다.
  기록 중에 페이지가 닫히면 마지막 자동 저장까지 남고 '중간에 끊김'으로 표시됩니다
- 기록 중 공이 왼쪽으로 밀리면 **★ 놓침 표시**(키보드 `M`)를 누릅니다. 의심스러운 순간은 자동으로도 표시됩니다
  (rev_count는 늘었는데 rpm 0 · ②가 0으로 떨어짐 · 프레임 간격 2.5초 초과 · 공이 왼쪽 끝에 닿음 · 연결 상태 변화)
- **저장된 기록** 목록에서 기록별로 공유(태블릿 공유 시트) / JSON / CSV로 꺼냅니다
- 연결되어 있는 동안은 화면이 꺼지지 않게 합니다 (Wake Lock)
- 페달 펌웨어의 읽기 전용 진단 명령을 함께 씁니다 (명령 정의는 페달 저장소 `docs/02-system-sequence.md` §5)
  - `DBG`: 회전 검출기 내부 상태 24필드를 0.5초마다 폴링. 회전 기각(사유 포함)·재락온·움직임 없음 판정·출력 0 을 자동 표시합니다
  - `CAP`: 기록 중에만 검출기 입력 파형(lz, ly, gx, gz · 100Hz)을 받습니다. 300초 상한이라 자동으로 다시 겁니다
  - `RS_G`: 연결 때 정지 판정 기준 등 검출 파라미터를 읽어 화면에 풀어 씁니다
  - 저장된 기록의 **DBG CSV** / **CAP CSV** 는 페달 저장소 `cardio_tool` 과 같은 형식이라 `tools/verify_phase_detector.py --csv` 로 재생할 수 있습니다
- **속도 추정 비교**: 페달의 avg_rpm·회전 확정·게임 ③ 과, 원시 파형 lz 에서 직접 구한 추정값(영교차 / 파형 모양 TEO / 결합, `js/cadence-est.js`)을
  같은 그래프에 그립니다. 각 값은 계산할 수 있게 된 시각에 찍히고, 아래 띠의 눈금이 각 방법이 새 값을 낸 순간입니다.
  비교를 위해 기록 중이 아닐 때도 CAP 을 받습니다 (끌 수 있음)
- `pedal-debug.html?sim`: 페달 없이 화면을 확인하는 시뮬레이터 (가정한 펌웨어 동작이라 실제 페달과 다를 수 있음)

## 구성

| 경로 | 내용 |
|---|---|
| `index.html`, `css/`, `js/` | 게임 본체 |
| `js/config.js` | 라운드 길이, 허용 구역, 목표 속도 변화 등 조절값 |
| `js/pedal.js` | 페달 입력 (키보드 / 센서 RPM을 하나의 RPM 값으로) |
| `js/pedal-link.js` | Cardio 페달 BLE 연결과 프레임 파서 (CardioArcade `ble/` 이식) |
| `js/cadence-est.js` | 원시 파형 lz 로 케이던스 추정 (영교차 · 파형 모양 · 결합) |
| `pedal-debug.html`, `js/pedal-debug.js` | 페달 센서 디버그 페이지 |
| `js/demo.js` | 운영 버전의 스테이션 흐름: 대기·결과·운영 메뉴, 무인 운영 장치 |
| `js/abilities.js` | 게임 성적 → 능력 축 가중치, 레이더 그래프 |
| `js/exercise.js` | 운동량: RPM → 거리, MET → 열량 |
| `css/themes.css`, `js/themes.js`, `js/fx.js` | 화면 스타일과 연출 효과 |
| `js/session-log.js` | 세션 로그 (문제·답·입력 장치 원시 입력). 형식: `docs/SESSION_LOG.md` |
| `js/games/` | 인지 게임 8종: 길 따라 그리기, 심볼 위치 외우기, 사칙연산 역산, 우세한 색 찾기, 빈자리 채우기, 숨은 순서 찾기, 가린 숫자 더하기, 사다리 타기 |
| `docs/DEMO_BRIEF.md` | 시연 행사 준비 작업 개요 (스테이션 흐름의 배경) |
| `docs/엑서게임_기획_슬라이드.pdf` | 기획 요약 슬라이드 |
| `docs/slides.html`, `docs/shots/` | 슬라이드 원본과 플레이 화면 스크린샷 |
| `docs/build/` | 스크린샷 촬영·PDF 생성 스크립트 (Node 22+, Edge 필요) |

## 슬라이드 다시 만들기

```bash
node docs/build/capture.js   # 게임을 자동 플레이하며 스크린샷 촬영
node docs/build/pdf.js       # slides.html → PDF
```
