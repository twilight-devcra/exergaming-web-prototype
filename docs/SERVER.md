# 바깥 서버 요구 사항

시연·운영 버전의 운영 메뉴 **자동 업로드** 칸에 적는 서버가 해야 하는 일입니다. 태블릿 쪽 코드는 `js/session-upload.js`(업로드)와 `app/members.js`(회원 기록 받아 오기)입니다.
이 동작을 바꾸면 이 문서를 함께 고칩니다.

서버는 없어도 됩니다. 칸이 비어 있으면 태블릿은 혼자 돌고, 세션은 태블릿(IndexedDB)에 남아 운영 메뉴 **전체 내보내기** 로 꺼낼 수 있습니다.

## 한눈에

| | 업로드 | 회원 기록 |
|---|---|---|
| 운영 메뉴 칸 | 업로드 주소 | 회원 기록 주소 (선택) |
| `js/config.js` 기본값 | `SESSION_UPLOAD.url` | `SESSION_UPLOAD.historyUrl` |
| 요청 | `POST <주소>`, 본문 = 세션 로그 하나 | `GET <주소>?user=<회원 번호>` |
| 성공 | 아무 2xx (본문은 읽지 않음) | `200` + JSON 목록 |
| 기다리는 시간 | 60초 | 6초 |
| 실패하면 | 나중에 다시 보냄 (세션을 잃지 않음) | 그 태블릿의 기록만 보여 줌 |
| 쓰는 버전 | 시연 모드(`?demo`), 운영 버전(`app/`) | 운영 버전만 |

두 주소는 같은 서버일 필요가 없지만, 회원 기록은 업로드된 세션으로 만들므로 보통 한 서버입니다.
**인증 키** 칸은 하나이고 두 요청에 모두 붙습니다.

## 공통

- **HTTPS**: 페이지가 `https://` 에서 열리므로 서버도 `https://` 여야 합니다 (브라우저가 `http://` 요청을 막는다). 개발 중 `http://localhost` 는 예외
- **CORS**: 페이지와 서버의 출처가 다르므로 서버가 허락해야 합니다
  - 허락할 출처: `https://twilight-devcra.github.io` (배포), 개발 중이면 `http://localhost:5173` (`node server.js`)
  - `OPTIONS` 사전 요청에 `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods: POST, GET`, `Access-Control-Allow-Headers: Content-Type, Authorization` 로 답합니다. 업로드는 `Content-Type: application/json` 이라 늘 사전 요청이 오고, 회원 기록은 키가 있을 때만 옵니다
  - 실제 응답(`POST` · `GET`)에도 `Access-Control-Allow-Origin` 이 있어야 합니다. 없으면 서버가 받았어도 태블릿은 실패로 보고 다시 보냅니다
  - 쿠키는 쓰지 않습니다 (`Access-Control-Allow-Credentials` 필요 없음)
  - CORS 가 틀리면 브라우저는 이유를 알려 주지 않습니다. 운영 메뉴에는 '연결 실패 (인터넷·주소·CORS 확인)' 로만 나옵니다
- **인증**: 키를 적었으면 `Authorization: Bearer <키>`. 키를 안 적으면 헤더가 없습니다
  - `js/config.js` 와 태블릿은 누가 봐도 되는 곳이므로 키는 비밀이 아닙니다. **'세션 올리기 + 회원 기록 요약 읽기'만 되는 키** 로 만들고, 세션 원본 읽기·지우기는 안 되게 합니다

## 업로드 — `POST <업로드 주소>`

판이 끝나면 태블릿은 세션을 먼저 IndexedDB 에 저장하고, 아직 안 보낸 것을 **오래된 것부터 하나씩** 보냅니다.

**요청**

```
POST <업로드 주소>
Content-Type: application/json
Authorization: Bearer <키>        (키를 적었을 때만)

{ "meta": {...}, "events": [...], "keys": [...], "capd": [...], "workout": [...], "samples": [...] }
```

본문은 세션 로그 하나 그대로입니다. 형식은 [SESSION_LOG.md](SESSION_LOG.md).

**서버가 해야 하는 것**

- **크기**: 페달로 5분 한 판에 약 0.6 MB, 가장 긴 15분이면 약 2 MB (대부분 `capd`). 본문 크기 제한을 **5 MB 이상** 으로 둡니다
- **같은 세션을 덮어쓰기**: 서버가 받고 답하기 전에 연결이 끊기면 같은 세션을 다시 보냅니다. `meta.device` + `meta.id` 를 키로 저장해 두 번 와도 한 건이 되게 합니다
  - `meta.id` 는 태블릿 안에서만 겹치지 않습니다 (기록 시작 시각, epoch ms). 그래서 `device` 와 함께 써야 합니다
- **받았으면 2xx**: 2xx 만 '보냄'으로 적힙니다. 응답 본문은 읽지 않으므로 빈 `204` 도 됩니다
- **실패 응답은 '나중에 다시'라는 뜻**: 태블릿은 2xx 가 아니면 상태 코드와 관계없이 (4xx 도) 멈췄다가 다시 보냅니다. 그리고 **그 세션이 지나가야 다음 세션을 보냅니다**. 그러니
  - 형식이 이상해도(예전 버전, 빠진 필드) 거절하지 말고 받아서 2xx 로 답합니다. 거절하면 그 태블릿의 업로드가 거기서 멈춥니다
  - 크기 제한(`413`)에 걸리면 마찬가지로 멈추므로 제한을 넉넉히 둡니다
  - 서버 장애·점검 중이면 5xx 로 답하면 됩니다. 세션은 태블릿에 남아 있다가 나중에 올라옵니다
- **다시 보내는 때**: 실패한 뒤 30초 → 1분 → 2분 … 최대 10분 간격. 그 밖에 인터넷이 다시 연결될 때, 5분마다, 새 판이 끝날 때, 운영 메뉴 **지금 보내기** 를 누를 때. 한 태블릿이 동시에 두 개를 보내지는 않습니다
- **예전 세션도 옵니다**: 업로드를 켜기 전에 태블릿에 쌓인 세션(같은 주소의 프로토타입 시연 모드 것 포함)도 올라옵니다. 이런 세션에는 `meta.version` 이 1 이고 `device` · `edition` 이 없을 수 있습니다. `device` 가 없으면 서버가 정한 값(예: 빈 문자열)으로 묶어 두면 됩니다

**알아 두면 좋은 필드** (자세한 것은 [SESSION_LOG.md](SESSION_LOG.md) 의 `meta`)

| 필드 | 쓸모 |
|---|---|
| `meta.device`, `meta.id` | 세션 하나를 가리키는 키 |
| `meta.edition` | `prototype` \| `app` |
| `meta.mode` | `test` \| `demo` (업로드는 `demo` 만 온다) |
| `meta.user`, `meta.guest`, `meta.userNew` | 운영 버전의 회원 번호 등. 회원 기록을 만들 때 쓴다 |
| `meta.station`, `meta.participant` | 시연 모드의 스테이션·참가 번호 |
| `meta.startedAt`, `meta.ended` | 시작 시각, 끝난 방식 (`abandoned` 는 결과 없이 끝난 판) |
| `meta.summary` | 점수·운동량·게임별 성적 요약. 원본(`events`, `capd` …) 없이도 대부분의 통계는 이것으로 된다 |

## 회원 기록 — `GET <회원 기록 주소>?user=<번호>`

운영 버전에서 회원이 로그인하면 그 회원의 지난 기록을 받아 달력과 '지난번' 을 채웁니다. 다른 태블릿에서 한 운동까지 보이게 하려는 것입니다.

**요청**

```
GET <회원 기록 주소>?user=12345674
Authorization: Bearer <키>        (키를 적었을 때만)
```

- `user` 는 8자리 숫자 회원 번호입니다 (끝자리는 Luhn 검사 숫자, `app/members.js` 의 `Members.valid`). 주소에 이미 다른 쿼리가 있으면 거기에 `user` 가 더해집니다
- 6초 안에 답이 없으면 포기하고 그 태블릿의 기록만 보여 줍니다. 이 요청은 로그인 화면에서 바로 나가므로 빨라야 합니다

**응답**: `200` 과 JSON. 아래 둘 다 됩니다.

```json
{ "sessions": [ { "at": "2026-11-03T05:12:40.118Z", "min": 10, "difficulty": "normal", "score": 4180, "device": "3f1c…", "sid": "1762146760118" } ] }
```

```json
[ { "at": "…", "min": 10, … } ]
```

항목 하나가 세션 하나이고, 업로드된 세션에서 이렇게 뽑습니다.

| 필드 | 뽑는 곳 | 쓰는 곳 |
|---|---|---|
| `at` (필수) | `meta.startedAt` | 달력의 날짜, 최근 기록, '지난번'. 날짜로 읽히지 않는 항목은 버린다 |
| `min` | `meta.session.min` | 최근 기록, 다음 세션 설정에 미리 골라 둘 시간 |
| `difficulty` | `meta.session.difficulty` (`relax` · `normal` · `challenge`) | 최근 기록, 미리 골라 둘 난이도 |
| `score` | `meta.summary.score` | 최근 기록 |
| `device`, `sid` | `meta.device`, `meta.id` (문자열) | 태블릿에 있는 같은 세션과 겹치지 않게. 둘이 같으면 한 번만 센다. 빠지면 같은 판이 두 번 보일 수 있다 |
| `level`, `distM`, `kcal` (선택) | `meta.summary.stats` 의 `level` 최댓값, `meta.summary.exercise.distM` · `kcal` | 지금은 쓰지 않음 (나중에 그래프용) |

- **어떤 세션을 돌려줄까**: `meta.user` 가 그 번호이고 결과 화면까지 간 것 (`meta.ended` 가 `abandoned` 가 아닌 것). 태블릿 기록도 결과 화면에서만 쌓입니다
- **순서·개수**: 순서는 상관없습니다 (태블릿이 시간순으로 다시 정렬한다). 달력은 최근 2년까지만 넘겨 볼 수 있으므로 그보다 오래된 것은 빼도 됩니다
- **기록이 없는 번호**: 오류가 아니라 빈 목록(`[]` 또는 `{ "sessions": [] }`)으로 답합니다. 손님이 처음 받은 번호는 서버에 아직 없을 수 있습니다
- **실패**: 2xx 가 아니거나 JSON 이 아니면 '지금은 서버에 연결하지 못해 이 태블릿의 기록만 보여 드려요' 가 나옵니다. 다시 시도하지는 않습니다 (다음 로그인 때 다시 묻는다)

**개인 정보와 남용 막기**

- 회원 번호는 이름 없는 무작위 번호이고, 돌려주는 것은 운동한 날짜와 점수뿐입니다
- 그래도 번호를 차례로 넣어 보는 것을 막으려면 이 주소에 요청 횟수 제한을 둡니다 (태블릿 한 대는 로그인할 때 한 번만 묻는다)

## 서버 없이 시험하기 (시험용 로컬 서버)

서버가 준비되기 전에 회원 기록 흐름을 시험하려면 운영 메뉴 → **자동 업로드** → **시험용: 회원 기록 서버 대신 이 태블릿의 세션 로그 쓰기** 를 켭니다 (또는 `js/config.js` 의 `SESSION_UPLOAD.localHistory: true`).

- 켜면 회원 기록 주소 대신 이 태블릿의 세션 로그(IndexedDB)에서 위 '회원 기록' 의 규칙대로 골라 같은 모양의 목록을 만듭니다 (`app/members.js` 의 `Members.localServer` · `Members.summarize`). 실제 서버를 만들 때 이 두 함수를 참고하면 됩니다
- 회원 기록 주소 칸은 꺼지고, 기록 화면에 늘 '시험용: 이 태블릿의 세션 로그를 서버 대신 썼어요 (N건)' 이 나옵니다. 실제 서버로 착각하지 않게 하려는 것입니다
- **주소 칸을 비워 둔다고 저절로 켜지지 않습니다.** 비어 있으면 지금처럼 서버 없이 이 태블릿의 회원 기록(localStorage)만 씁니다
- 업로드에는 영향이 없습니다. 업로드 주소가 비어 있으면 아무것도 보내지 않고, '보냄' 표시도 남기지 않으므로 나중에 실제 서버를 적으면 쌓인 세션이 모두 올라갑니다
- 한 태블릿 안에서 도는 것이라 다른 태블릿의 기록은 보이지 않습니다. 로그인할 때마다 세션 로그를 모두 읽으므로 세션이 많이 쌓인 태블릿에서는 느릴 수 있습니다

## 시험해 보기

1. 운영 메뉴 → **자동 업로드** 에 주소와 키를 적고 **지금 보내기**
2. 옆의 상태 줄이 '모두 보냄 · 마지막 성공 HH:MM' 이 되면 됩니다. '실패: …' 면 그 이유와 다음 시도 시각이 나옵니다
3. 회원 기록은 운영 버전(`app/`)에서 회원으로 로그인해 달력 아래 문구를 봅니다: '다른 태블릿의 기록까지 모두 보여 드려요' 면 받아 온 것입니다
